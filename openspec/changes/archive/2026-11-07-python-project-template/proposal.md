# Proposal

## Why

Каждый новый Python-сервис начинается с одной и той же рутины: каркас FastAPI-приложения, конфигурация из переменных окружения, логирование, телеметрия, тесты, линтер, проверка типов, Dockerfile, dev-окружение. Ручная настройка занимает время и порождает расхождения между проектами. Нужен параметризуемый шаблон, который одной командой выдаёт готовый к разработке сервис с едиными соглашениями.

## What Changes

- Добавить Copier-шаблон с параметрами генерации (имя проекта, версия Python) и валидацией имени (kebab-case)
- Включить в шаблон каркас сервиса:
  - фабрика FastAPI-приложения с endpoint `GET /health`
  - настройки на pydantic-settings из переменных окружения (`.env` поддерживается), базовые поля + наследование для своих
  - структурное логирование на structlog: человекочитаемый вывод в debug-режиме, JSON в рабочем
  - опциональная телеметрия OpenTelemetry (трейсы + логи через OTLP), отключаемая переменной окружения
- Включить инструменты качества: ruff (line-length 119), mypy strict, pytest с coverage; единый Makefile (`lint`, `fmt`, `test`, `run`)
- Включить контейнеризацию: multi-stage Dockerfile на uv (targets: dev/builder/release), non-root пользователь, entrypoint на uvicorn, compose.yml для локального запуска
- Включить dev-окружение: devcontainer и конфигурации VS Code (запуск uvicorn с отладкой, запуск тестов)
- Включить CI-скелет: lint + test на push/MR
- Что намеренно **не** входит (вне scope): helm/k8s-манифесты, service discovery, внешние хранилища секретов, GPU-опции, приватные registry и любая организационная инфраструктура; отдельная библиотека-ядро не создаётся — вся «обвязка» живёт прямо в сгенерированном проекте

## Capabilities

### New Capabilities

- `project-generation`: параметризованная генерация нового проекта из шаблона одной командой с валидацией входных параметров
- `service-scaffold`: готовый каркас сгенерированного сервиса — HTTP-приложение с health-проверкой, конфигурация из окружения, логирование, телеметрия, тесты, инструменты качества кода, контейнерный и локальный запуск, dev-окружение

### Modified Capabilities

(нет — существующих спецификаций нет)

## Impact

- Репозиторий превращается в шаблон: `copier.yml` + каталог `template/`; для разработки шаблона нужны copier и uv
- Сгенерированные проекты зависят от: fastapi, uvicorn, pydantic, pydantic-settings, structlog, opentelemetry-sdk (+ инструментация FastAPI), pytest (+asyncio, cov, mock, httpx), ruff, mypy
- Для полного цикла нужны Docker (сборка образа, compose) и VS Code (devcontainer) — обязательными только Docker/uv
