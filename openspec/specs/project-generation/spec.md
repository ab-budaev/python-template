# project-generation Specification

## Purpose

Позволяет создать новый Python-сервис одной командой из параметризуемого шаблона, получая проект с согласованной структурой и рабочим каркасом, а не пустый каталог.

## Requirements

### Requirement: Параметризованная генерация проекта

Шаблон ДОЛЖЕН (MUST) поддерживать генерацию проекта по команде копирования шаблона с интерактивным запросом параметров. Обязательные параметры: имя приложения; опциональные: версия Python (со значением по умолчанию).

#### Scenario: [P0] Генерация с параметрами по умолчанию

- **GIVEN** разработчик запустил генерацию из шаблона
- **WHEN** он принимает значения по умолчанию для опциональных параметров
- **THEN** в целевом каталоге создан проект, имя которого равно указанному имени проекта, а версия Python соответствует значению по умолчанию

#### Scenario: [P0] Генерация с явной версией Python

- **GIVEN** разработчик запустил генерацию из шаблона
- **WHEN** он явно указывает версию Python
- **THEN** созданный проект настроен на указанную версию Python (файл версии и ограничение в метаданных проекта)

### Requirement: Валидация имени приложения

Шаблон ДОЛЖЕН (MUST) отклонять имена приложений, не соответствующие формату kebab-case (строчные буквы, цифры, дефисы; начинается с буквы или цифры), и сообщать пользователю требуемый формат.

#### Scenario: [P0] Валидное имя принимается

- **GIVEN** запущена генерация проекта
- **WHEN** разработчик вводит имя `my-app`
- **THEN** генерация продолжается без ошибок валидации

#### Scenario: [P0] Невалидное имя отклоняется

- **GIVEN** запущена генерация проекта
- **WHEN** разработчик вводит имя `My_App`
- **THEN** генерация останавливается с сообщением о требуемом формате имени

### Requirement: Переиспользование имени приложения в артефактах

Сгенерированный проект ДОЛЖЕН (MUST) использовать имя приложения единообразно во всех текстовых артефактах: имя каталога проекта, имя сервиса по умолчанию, имя Docker-образа, заголовок README.

#### Scenario: [P0] Имя подставлено во все артефакты

- **GIVEN** проект сгенерирован с именем `my-app`
- **WHEN** разработчик открывает файлы проекта
- **THEN** каталог проекта называется `my-app`, приложение идентифицирует сервис как `my-app`, Dockerfile собирает образ с именем `my-app`

### Requirement: Воспроизводимость генерации

Шаблон ДОЛЖЕН (MUST) сохранять выбранные параметры внутри сгенерированного проекта, чтобы повторная генерация с теми же ответами давала идентичный результат и позволяла обновлять проект при выходе новых версий шаблона.

#### Scenario: [P1] Повторная генерация даёт тот же результат

- **GIVEN** проект сгенерирован и параметры сохранены внутри него
- **WHEN** разработчик повторно запускает генерацию с теми же ответами на вопросы
- **THEN** содержимое сгенерированных файлов не отличается от первого прогона
